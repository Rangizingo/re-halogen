## Decoded facts

- 6-bit row (hc6 and hcup6): 272 bytes per row, plane stride 0xaa000 (2560 * 272), 4 planes. 160 bytes of nibbles (32 weights per lane in 16 bytes), 80 bytes of 2-bit high parts (8 bytes per lane at +160), 5 group dwords at +240 (one per two lanes). Only lanes 0..9 of each 16-lane group load (`:252505` v_cmpx 10). Weight q = nibble | (hi2 << 4), value = bf16_rne(fma(q, scale_f16, bias_f16)); chain of 16 `v_dot2_f32_bf16` from 0; xor butterfly 8,4,2,1; epilogue identical to hc8 (sigmoid, wm fma chain, `* 0.25`).
- hc6 LqGrp role: lq6 layout (K/2 + K/4 + K/16 bytes, row stride aligned to 16), 32-element units, 8 waves per row when R<=8 else 2 waves and 4 rows per block; same E epilogue as hc8's lq8 role. Same decode as g03's `k_lq6w_grp` (`lq6w.hip` in worktree agent-a3137ad23acfdd8fd).
- Kernarg layouts of hc6_fused and hc6_fused3 are identical to hc8's (checked in `rewrite/harness/kernargs.json`), so g11's hc8 specs were reused with the weight blob sizes changed (3481600 to 2785280, member blobs to 2080-byte rows).
- Cite caveat: the line cites in `hc6.hip` for the hc6 path and the lq6 member pick are approximate ranges read from the `hcup6<1>` and `hc6_fused<1>` listings; wait/scatter/bump keep g11's hc8 cites, marked `hc8-f1` / `hc8-f3_1`, with the hc6 equivalents listed above them.

## Infrastructure note

Ai-core /tmp hit its quota during the run (hipcc "Disk quota exceeded"; some early runs returned 0 rows). The run scripts retried until each spec printed 6 rows, and the final tables were regenerated from scratch after that, so every row comes from one clean pass.
