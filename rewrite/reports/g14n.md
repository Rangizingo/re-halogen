# g14n: NaN sign of the ht_gemv rewrites (refuter finding on PR #24)

Result: all 94 ht_gemv instances MATCH bitwise on 1,275 (instance, spec) pairs, 5,133 compare.py rows, 0 MISMATCH. Table `rewrite/tables/g14n.md`.
Fixed copies: `rewrite/kernels/ht_gemv_b_c.hip` (from ht_gemv_b.hip, 30 instances) and `rewrite/kernels/ht_gemv_c.hip` (g32's copy of ht_gemv.hip, 64 instances, fixed in place per the orchestrator).
`rewrite/superseded.tsv` gets `ht_gemv_b.hip -> ht_gemv_b_c.hip`. ht_gemv_b.hip is untouched.

## Cause (operand order of a commutative float op when both inputs are NaN)

The refuter's repro (x and sv both NaN) differs only in the sign bit of NaN outputs (vendor 0x7fc0, rewrite 0xffc0). Hardware returns the first NaN source (src0) of a
two-NaN op. Vendor and rewrite multiply by sv in opposite order.

- Vendor dn_g<3,8,2,2> `kernels-disasm-v2/codeobj_53000.s:1151876`: `v_fma_mix_f32 v12, v23, v22, neg(0) op_sel_hi:[1,0,0]` (src0 = sv as f16, src1 = y = wht * 0x3db504f3). sv NaN wins.
- Rewrite before (`k_b_dn_g_3_8_2_2`, hipcc -O3, 0x8166C): `v_mul_f32_e32 v9, v11, v9` (src0 = y, src1 = cvt(sv)). y is a hardware default NaN (negative, from inf-inf / 0*inf in the dot and WHT) and wins.
  The source said `(float)sv * y`; the compiler commutes it freely.

Ranked candidates considered before editing: (1) operand order of the sv multiply, confirmed; (2) bf16 NaN rounding (v_bfe_u32 / v_add3_u32 0x7fff, same code on both sides, cannot flip a sign), ruled out;
(3) WHT add/sub operand order upstream, ruled out for dn by the x-only specs matching (sv-only and x-only matched in the refuter's run), but it is the cause for gu_gs (below).

## Fix

- `dn_store` (dn, dn_t incl. fold, dn_ts, dn_g token and dense paths) and the G, U multiplies of `gu_finish` (gu, gu_t, gu_ts): `mulsv()` emits the vendor instruction by inline asm
  (`v_fma_mix_f32 d, sv, y, neg(0) op_sel_hi:[1,0,0]`), because `__builtin_fmaf(sv, y, -0)` is folded back into a commuted v_mul_f32.
- gu_gs (`gu_finish<true>`, ht_gemv_c.hip only): the vendor compile differs (`codeobj_53000.s` gu_gs<3,8,2>: `v_mul_f32 v30, v30, v8` = y * sv, y first; `v_mul_f32 v30, v31, v30` = U * q;
  first stage `v_fma_f32 z, su, +-rb`; bit-2 WHT stage adds `v_add_f32 v30, v34, v29` = t3 + t1 and `v_add_f32 v39, v28, v36` = t7 + t5, reversed against the generic order).
  These are pinned with asm helpers (`mul_asm`, `fma_asm`, `fmaneg_asm`, `add_asm`, `sub_asm`) in the vendor order. Only sv-only NaN specs exposed it (diff 172 to 288 of 25600 before).
- Diff size: ht_gemv_b_c.hip +5/-1 lines in dn_store (+ header); ht_gemv_c.hip +helpers and a `GS` template flag on gu_finish.

## Caveats

- Not covered: NaN in the Hamming-weight (w) buffers (random bytes already decode to finite weights), NaN in index buffers, exponent/denormal edge values other than the existing `_edge` specs.
- Existing b-group specs still point at ht_gemv_b.hip in the repo; the runs here used `--rewrite-src ../kernels/ht_gemv_b_c.hip`. Repointing them is a sed on `rewrite_src`.
- Run: Ai-core ~/g14n, three compare.py workers in parallel (`.service-down` window), CMP_TMP on disk.
