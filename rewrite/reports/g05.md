## Findings worth a follow-up

- The `.long` words in the listing are VOP3 ops llvm-objdump cannot print. Decoded from the opcode field: d72c = v_mul_lo_u32,
  d72d = v_mul_hi_u32, d73c/d/e = v_lshlrev/lshrrev/ashrrev_b64, d7006a.. = v_add_co_u32, d4xx = VOPC-E compares. Inferred, and the compare run confirms.
- NaN operand order matters on random-byte inputs: a plain fmaf swapped operands and gave a different NaN payload; inline asm
  (v_fma_mix_f32, v_mul_f32, v_cvt_f32_f16) pins the order. The u8 specs (garbage LUT and scales) match.
- LUT scheme (exp_gu_w, exp_dn_w): 256-entry LDS table T[b] = bf16(W_f32[b&15]) | bf16(W_f32[b>>4])<<16, W_f32 = first 16 f32 of the weight buffer; one dot2 per x dword and weight byte, 16-step chain per 32-element group (L:2401142-2401167).
- Affine (aff) format: Q4_K-like. Per 32-element group (scale byte, min byte) at AffDev[2]+row*AffDev[3]+2g; f16 (d, dmin) per 256 elements at AffDev[4]+row*AffDev[5]+4(g>>3); acc += (d*sc)*Pq - (dmin*mn)*Px, Px = x dot (1,1). B=5 adds a bit plane at AffDev[1]+row*320+4g (gate_up) whose set bits are bf16 16.0 pairs on the same dot2 chain. exp_dn_aff is Q5 only, with a per-group (d,dmin) pair at AffDev[2]+row*AffDev[3]+4h and plane at AffDev[1]+row*80+4h.
- K (prefetch) and E (HALOGEN_LQ4W_SH) of k_exp_gu_w/aff, and R (8/16/32 lanes per row) only reschedule the same arithmetic; all 36 instances MATCH with one templated body.
- k_exp_dn_w<1> ignores expert and row in weight/scale addresses (reads the same 320 bytes for every row); w<2> replaces the dot with float(w0^w1^w2^w3) and loads no x.
- k_deq_q4cp_probe: B=1 has no memory reads (w = g*0x9e3779b1, scale = 1 + 0.25*(g&7); g, not column c); B=2 stores nothing unless a thread's xor-checksum equals 0x9e3779b9, then writes u16 1 at y[tid] (the undecoded `.long 0x7e003881` sets the data register to 1, observed); B=3 stores w+k*s integer words; B=4 reads with row&0xff.
  Specs probe_*_2 use an iota fill and a hand-solved DeqCb LUT (hex arg) so thread 0 reaches the magic checksum; only y[0] changes.
- k_q4moe_items traps (s_trap 2) when cfg[513] != n; the rewrite uses __builtin_trap. Not exercised. Negative per-expert counts make tile indices overlap (racy in both kernels), so specs use monotonic offsets.
