## Why the 274 GAP rows went away (tool fixes, each with tests that failed first)

The orchestrator's triage assumed most float gaps were real (missing expf clamp, ln2 split, -1e29 sentinel, 1.0, -log2e,
1/sqrt(128), 0.25). They were not missing from the rewrites; the tool could not see them.

1. Integer operand roles (by role, not bit pattern): any instruction whose source type is an integer type (`_b32 _u32 _i32 _u16 ...`),
   `v_permlane*`, `v_perm_b32` selectors, `*_mul_hi_*` magic multipliers, `v_cvt_f32_u32` sources. Data movers (`*_mov_b32`, `v_cndmask_b32`) are
   followed through registers: a literal moved or cndmask-selected into a register counts as integer when its readers (until the register
   is rewritten, through further movs and cndmasks) are integer-role, and as float if any reader is a float op. Byte-selector shaped
   literals (every byte 0..7, e.g. 0x76543210, 0x07060302, 0x01000504) tolerate register-reuse noise when at least one integer reader exists.
   Carry-out registers (`v_div_scale`, `v_add_co_u32`) are not reads. Covers 0xfedcba98, 0x76543210, 0x07060302, 0x0c0c0c0c, 0x07070707,
   0x07030602, 0x05010400, 0x66666667, 0x0f0f0f0f, 0x64006400, 0x0ffffffe, 0x1ffffffc and the like.
2. Compiler expansions: 32-bit udiv (`v_rcp_iflag_f32`, 0x4f7ffffe), 64-bit udiv (`v_rcp_f32` with 0x5f7ffffc: 0x4f800000, 0x2f800000,
   0x5f7ffffc, 0xcf800000), logf denormal prescale (`v_log_f32` with `v_cmp ..., 0x800000` and cndmask 0x4f800000). For
   `k_dn_recur_rows` 0x4f800000 is the logf prescale on `1 + exp(x)` which is always >= 1, so the prescale branch (arg < 2^-126) cannot run in either kernel.
3. Device-function calls (the big one, about 120 rows): the rewrite kernels call non-inlined `__device__` helpers (`gu_finish`, expf
   helpers, WHT, silu). hipcc emits them as separate symbols reached by `s_getpc_b64; s_add_u32; s_addc_u32; s_swappc_b64`. The tool read
   only the kernel symbol, so every constant living in a helper looked absent: 1/sqrt(128) 0x3db504f3, 1.0, -log2e 0xbfb8aa3b, the whole
   libm expf set (0x42b17218, 0xc2b17218, 0x42ce8ed0, 0xc2ce8ed0, 0x3fb8aa3b with 0x32a5705f / 0xb2a5705f, 0x3d800000, 0xefa18f08, 0xf149f2ca),
   and 0x3e800000 in hc6/hc8 fused. The tool now resolves call targets (pc-relative: address of the `s_add_u32` + 64-bit offset) and unions
   the literals of every transitively called function, for the rewrite and for the vendor kernel. The "1.0 / -log2e missing in 104
   instances" case was this, not an inline-constant spelling or a neg modifier (sign flips were already handled).
4. `.rodata` words of the rewrite object are counted as present (a `static __device__` table compiles to data, not immediates). Covers the
   NF4 LUT in `k_dv_quant` (0x3da30000 ... 0xbf320000).

## Real float gaps: none remain; one explained exception

`k_dv_quant` 0xbd4ccccd (-0.05f). The vendor loop computes `f = fma(float(i), -0.05f, 1.0f)` for i = 0..7 at run time (`s_fmaak_f32`, listing
:8743). The rewrite (`rewrite/kernels/dv_quant.hip:65`) is unrolled by hipcc and the fma is folded at compile time; its ISA holds the results
1.0, 0.95, 0.9, 0.85, 0.8, 0.75, 0.7, 0.65 (0x3f733333, 0x3f666666, 0x3f59999a, 0x3f4ccccd, 0x3f400000, 0x3f333333, 0x3f266666). I checked
that these are the exact fma values rounded to f32 (python, double arithmetic then f32 round). The constant -0.05 still reaches the output
through those values; the `dv_quant8_*` specs MATCH bitwise. Recorded in `rewrite/const-audit-exceptions.tsv`.

No new `<family>_c.hip` file or spec was needed: every constant the vendor uses is present in the matching rewrite, so there was no
rewrite to fix. Counts of rewrites changed: 0.

## What the audit does not prove

Presence of a constant in the rewrite ISA does not show it is used the way the vendor uses it. For the expf clamp family the existing
specs already reach the clamp arguments: `attn_fa2_*_edge` (q, k in +-40, gate +-120; g07 negctl: clamp -103.28 to -96 MATCHes, so the
clamp is unobservable in bf16 output, recorded in `rewrite/reports/g07.md`), `attn_qs_*_ext/_clamp/_low`, `ht_gemv_gu_*_edge`
(sv +-40: exp2 overflow and SiLU saturation, g14 negctl MISMATCH on the exp scale). Only 3 of the 26 attn_fa2 instances have a dedicated
`_edge` spec; the other 23 share the same helper code (`expf` / `expneg` in `attn_fa2.hip`), so their clamp behavior is the
same function, but that is inferred from shared source, not measured per instance.

Heuristic limits of the tool (all err toward reporting a gap, except item 1): register tracking is straight-line text order, not a control-flow
graph; integer-role byte-selector shaped literals ignore float readers of the same register; `.rodata` includes kernel descriptors, so
a vendor float equal to a descriptor word would hide.
