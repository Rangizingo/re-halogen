## Facts proven by MATCH (all bitwise, seeds 1-3, two sizes each)

- HT weight decode, 4 and 3 bit, is the unified rule of `analysis/closure/ht-decode.md` ("Unified decoder"): window of 16 bits of the tile words read in
  reverse order as one LE bit string, start `BITS*(255 - (8t + c)) mod 256*BITS`; hash `x*0x83dcd12d`, byte sum plus 0x6400 as f16 bits, weight =
  `fma_f16(1024+S, 0x1eee, 0xc931)`. This is the closure doc's 3-bit claim, now proven end to end (random bytes, all 8 weights of every lane).
- Column of lane weight c is `8h + c` (h = lane/16); dot pairs (c0,c1),(c2,c3),(c4,c5),(c6,c7) with `v_dot2acc_f32_f16` in that order.
- dn item `{expert, tile, begin, end}`: W offset `expert*2560*640*B/8 + tile*128*640*B/8`, x row `min(begin,end-1)` (640 halves), out row `begin`, written only if end > begin.
  Wave w owns column tiles 5w..5w+4; gate_up kernel: 20 column tiles per wave, 16 row tiles (gate 8 then up 8), x row `tok[min(begin,end-1)]`.
- Wave partials: own + other half (permlanex16), LDS, wave 0 sums waves 0..7 starting from `0 + P0`, 128-point WHT (j stages 1,2,4 then lane xor 1,2,4,8; lane with the bit
  set computes `partner - x`), times the literal `0x3db504f3` (NOT the nearest f32 to 0.0883883506, which is `0x3db504f4`; that off-by-one-ulp literal in my first draft was found with a
  small ISA interpreter run on the vendor listing and caused 1-ulp f16 flips in gu), times sv.
- gu: `G = sv_g * (wht_g * c)`, `U = sv_u * (wht_u * c)`, `Z = U * (G / (1 + exp2(G * -1.4426950216)))` (IEEE division, `v_exp_f32`), then the fused first stage of the
  second WHT: `t[2m] = fma(Z[2m], su[2m], rn(Z[2m+1]*su[2m+1]))`, `t[2m+1] = fma(Z[2m], su[2m], -rn(...))`, remaining WHT, `v_fma_mixlo_f16(o, c, 0)` (f16 of the exact product).
- dn output is bf16 RNE of `sv * (wht * c)`.

## Specs and sensitivity

- dn specs use 160 items (all 20 tiles, 8 positions, experts 0-2, one item with end == begin); gu specs 80 items (5 tiles, 16 positions, experts 0-1). Item arrays are
  built by a 3-line scratch script into `/tmp/g14/*_items_b.bin` on Ai-core (`file` fill); `x_*.bin` debug files likewise. Regenerate with `struct.pack("<4i", e, tile, begin, end)`
  rows: dn `((p+t)%3, t, p, p+1+(t%2))` for p<8, t<20; gu `((p+b)%2, b, p, p+1+(b%2))` for p<16, b<5.
- `_small`: x in +-0.001 (outputs reach f16 subnormals in gu). `_edge` (gu): x in +-3, sv in +-40, so G reaches exp2 overflow and SiLU saturates.
- dn writes bf16 so a 1-ulp f32 error shows up in about 1 of 65k outputs; the dn main specs alone would not catch a wrong last-bit constant. The negative control N1 below shows a
  flip only after 8+ seeds. Treat dn constants as verified from the listing (`@A8668C`), with the data check weaker than for gu.
