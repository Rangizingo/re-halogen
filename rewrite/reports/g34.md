## R (real): attn_fa2 0xffff, 26 instances

0xffff is the vendor's default "all 16 key columns selected" mask (v_mov 0xffff at 1513000:15462 for <1,1,true,5,1,true>, same in all 26). When `FaSel.ids != null` the vendor builds a per-row column mask from sorted block ids and `cnt` (:15462-15790) and, when `FaSel.tilemask != null`, skips key tiles whose bit is clear (:15225-15236). Excluded columns are treated like causal-masked ones (max/exp/sum skip them, P=bf16 0). The original `attn_fa2.hip` ignores `fs` entirely (g07 listed this as "not exercised").
- Reaching specs (new): `attn_fa2_<A_B_C_D_E_F>_sp.json` (ids + tilemask from `specs/g34_data/*.bin`, sel base 0/13/26), `_sp2.json` (sel base 60/100/140 so tiles are skipped then processed), plus `_spids`, `_sptm` isolation specs.
- Result before the fix: original rewrite on `attn_fa2_1_1_1_5_1_1_sp` MISMATCH, 6 of 6 rows (276139 of 295040 elements differ, seed 1 N=48).
- Fix in a copy: `rewrite/kernels/attn_fa2_s.hip` (sp_mask, tile skip, ok mask). Two findings: (1) the id search is a persistent per-row pointer; nibble k of tile t is set when block 4t+k >= (row+sel0+1)/4 or listed. (2) for A=2 with OPT bit 1 (2,3,6,7) the vendor stages the next tile's K and V (scratch prefetch, 1513000:161090-161121 for <2,1,true,3,0,false>) in the previous EXECUTED iteration, so after a skipped tile the next tile reads the staged data of the wrong tile; the copy reproduces this (A=2 and OPT&2 only). A=1 has no such staging (tested: the model breaks A=1).
- Re-run after the fix, all 26 instances, seeds 1,2,3, N=48 and 100: `_sp` 6/6, `_sp2` 6/6, existing dense spec on the copy 6/6 (468 MATCH rows, `rewrite/tables/g34.md`).
- Overlap with g25: the copy is built from the ORIGINAL attn_fa2.hip (per-sub-tile `ntiles`). The block-wide loop bound (g25, attn_fa2_c.hip) is independent of these changes; merge both into one file and point `rewrite/superseded.tsv` at it. The 0xffff exception line in g34.tsv exists only so the audit passes until then. 0xffff relation to the loop bound: none (it is the sparse mask default).
