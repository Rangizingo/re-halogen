## What each blocked group turned out to be

**b1=F** (listing 209568-215210). Kernarg +0x08, +0x28, +0x30 are f32 copies of mir0, mir1, mir2 (same indexing as the f16 arrays: [T][48][128], [T][48][128], [chunk][48][64][64]). Inferred from use order: +0x30 is used pre-loop with a 256 B row pitch (mir2); +0x28 is used first in the chunk (X1, mir1); +0x08 later (X2, mir0). Every conversion is `v_fma_mix{lo,hi}_f16 x, s22, 0` with s22 = 16.0 (`s_mov_b32 s22, 0x41800000`; all 1440 mix ops use s22), so the f16 operand is f16(16*x), the value the b1=T path reads pre-scaled. Global b128 loads 40 to 80 and +320 conversions (128 + 128 + 64 per lane) fit. Masking and ragged handling are identical to the f16 path (N=100 MATCH).

**b2=T**: the 64 unrolled k-bound guards give the same results as the existing code for k = 128 and k = 100. The rewrite needed no change (4 of 4 MATCH). Not probed: k below 64, k = 0.

**A=4** (NC=32, NG=2): g09's body was already generic in NG except the state update, now a tile loop `tl = w; tl < 8*NG; tl += 4` (d-block `tl&7`, column group `tl>>3`). Each tile is an independent 4-step WMMA chain, so the wave-to-tile map changes no bit (listing: 16 WMMA per wave at 292885-293028 = 4 tiles x 4 token blocks). grid.y = 4. 5 of 5 MATCH.

**i2 = 4, 5, 6** (not clock probes; ablations of the state update, all b3=F):
- All three skip the Kt build: kernarg +0x00/+0x10/+0x78 are never s_loaded, the E1 exp is gone (one exp in the prologue at 218827, one for exp(G) at 221278 in the i2=5 listing), so S_new = exp(G)*S.
- i2=4 (215210-218565): no Kt region in LDS, WMMA 112 to 80, S scaled by unrolled `v_fma_f32 x = fma(El, x, 0)` (64 fma, 2addr ds ops, around 217934-218000).
- i2=5 (218565-222130): WMMA chain kept (112) but no ds_store ever writes Kt. Vendor output is identical across two runs and equals "Kt term = 0", modeled as `fma(2^-8, 0, El*S)`. Caveat (inferred): relies on the LDS being zero (or the product exactly zero) at launch; verified only by the MATCH rows.
- i2=6 (222130-225341): loop of `v_mul_f32 El*S` over the slab (224734-224770).
- i2=4 and i2=6 differ only in the sign of zero. `i24_negzero` and `i25_negzero` (out all -0.0) show the vendor gives +0 and the rewrite agrees. For i2=6 the vendor result equals the -0 input bits, which the harness rejects as UNTOUCHED, so no i2=6 negzero spec is kept; mul vs fma-with-0 for i2=6 rests on the listing only.
