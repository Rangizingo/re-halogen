## What the kernels do (listing cites are in the .hip comments)

- q4 layout is the g04 layout (16 f32 table, 4-bit codes, f16 scale per 32) with a bf16 result: `w = bf16_rne(f16 scale * lut[code])`, `acc = fma(bf(x), w, acc)`, per-slot LDS tree starting at B/2, bf16 RNE store with no NaN special case. Output index: single `c[y*gridDim.x + x]`; m `c[y*ldc + x*R + t]`; mt `c[k*ldc + x*R + t]` with token k at `x + k*K`.
- Template args of the mt kernel are (R rows per block, T tokens, U unroll, B block size). Read from group_segment in kernargs.json: R*B*4 + 64 bytes in every instance. U changes only the unroll (inferred from R*T accumulators for every U, settled by MATCH). In the rewrite U is a real `#pragma unroll U`.
- q8 (`codeobj_53000.s:19418-19650`): row stride K + K/16 bytes; u8 codes then one 4-byte entry per 64 elements at byte `(i>>4)&~3` holding two f16, low = scale, high = offset. `w = bf16_rne(fma(float(u8), scale, offset))` (single v_fma_mix_f32 with op_sel). Block 256, output `c[y*ldc + x]`, ldc is kernarg+32.
- q8s32 (`:20207-20435`): row stride align16(K + K/16); int8 codes then one f16 scale per 32 elements at byte `(i>>4)&~1`; `w = bf16_rne(fma(scale, float(i8), -0))`. Same tree and store as q8.
- No kernel here has a float multiply followed by a separate add: every multiply-add is an explicit `__builtin_fmaf` (matching v_fmac / v_fma_mix) and the tree uses adds only, so the `fp contract(off)` pragma was not added. No element-wise f32 kernel, so no dense sweep spec.

## Edge specs (second addendum on small magnitudes)

There are no epsilons, clamps or guards in these kernels. The magnitude-only behaviours are f32/f16 denormals and the RNE bias.
- `_small` specs: q values near 1e-3 (q4: bf16 +-0.001; q8/q8s32: f16 +-0.001).
- `_edge` specs: q4 bf16 +-1e-34 so f16(scale) * lut lands in f32 subnormals (outputs are bf16 values near 1e-38 and below, checked by dumping the vendor output); q8 f16 +-1e-5 (f16 subnormal scales).
- Lesson recorded: the first q4 edge spec used +-1e-37 and produced all-zero outputs on both sides, so it proved nothing. It was caught by dumping vendor outputs, replaced by +-1e-34, its rows and negctl rows were removed and regenerated. The other specs' outputs were non-trivial (q8 edge dump checked).
- Result: vendor and rewrite agree bitwise on all edge/small specs, so the vendor and a default hipcc build treat denormals the same here.

## Findings and follow-ups

1. No row guard in m/mt and no K tail logic beyond the strided loop; grid.x must equal ceil(rows/R). Specs use grid.x = 3.
2. q8 scale area per row is ceil(K/64)*4 bytes but the row stride only reserves K/16 bytes; for K=1000 the last entry overlaps the next row's first bytes. Both kernels read the same bytes so they agree; real weights use K a multiple of 64.
3. Weights in specs are random bf16/f16 bit patterns (one buffer per spec, no multi-segment fill in the harness), so code bytes are uniform only in their low byte. A harness fill that mixes dtypes per byte range would give uniform codes; not needed for MATCH.
4. U (unroll) gets distinct rewrite instantiations but the unrolled loops cannot be distinguished from U=1 by output; the rows prove equivalence, not that the vendor schedules the same way.
5. Large instances (mt<32,8,4,64>, 256 accumulators) compile with scratch spills in the rewrite; results still match.
