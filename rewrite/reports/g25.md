## Root cause

The vendor trip count is per block, not per 16-row sub-tile, and it is clamped to n - 1. The rewrite (`attn_fa2.hip:97`, `lastpos = row0 + 15 + base`) used the sub-tile's own last row with no clamp. Listing: `kernels-disasm-v2/codeobj_1513000.s`, instance `k_attn_fa2<2,1,true,5,1,true>` (starts :126335):

```
126412  s_or_b32 s27, s27, 31          s27 = (tile << 5) | 31 (s27 = s29 << 5 at :126363): last query row of the whole 32-row block
126413  s_add_i32 s0, s18, -1          s18 = n (kernarg +0x38)
126416  s_min_i32 s0, s27, s0          min(block last row, n - 1)
126418  s_add_i32 s0, s0, s28          + sel[0]
126419  s_cmp_lt_i32 s0, -15           (:126553 s_cbranch_scc1 -> epilogue: no tile at all below -15)
126557  s_lshr_b32 s2, s2, 28 ; 126559 s_add_i32 s0, s0, s2 ; 126561 s_ashr_i32 s16, s0, 4     s16 = trunc(s0 / 16) = last tile index
126786  s_add_i32 s1, s11, 1 ; 126787 s_cmp_eq_u32 s11, s16 ; 126789 s_cbranch_scc1 (exit)     do-while over tiles 0..s16 inclusive
```

Every A=1 instance has the same sequence with `(tile << 4) | 15` (`s_or_b32 s0, s0, 15` + `s_min_i32` + `s_cmp_lt_i32 s0, -15`, for example :14850-14856 for `<1,1,true,5,1,true>`). Grep over all 26 instance bodies shows the same `or 31|15`, `s_min_i32`, `-15` triple in each (windows starting at :14773 ... :229100; the `<2,1,true,2|3|6|7,0,false>` instances order the compare differently, the `or 31` and `s_min_i32` are present).

Effect: with A=2 the sub-tile 0 (rows 0-15 of the block) runs the key tiles of sub-tile 1 too, and the last block clamps to n - 1. A tile that is fully masked for a row still runs the online-softmax update. With m_old in (-1e30, -1e29] the alpha guard (`v_cmpx_lt_f32 0xefa18f08`, :128152-128166) forces alpha = 0, wiping O and l, giving 0 * (1/0) = NaN. With V = inf at a masked key, P = 0 * inf = NaN in the WMMA. The rewrite never ran that tile for the early rows, so it stayed finite.

Ranked candidates before the change (the first one was confirmed by the listing and by 1578 MATCH rows):
1. Block-wide bound with the n - 1 clamp (listing lines above). Explains the refuter's partial probe: `lastpos += 16 * (1 - sub)` gives the block bound but not the clamp, so block 1 of N = 48 (rows 32-63, n - 1 = 47) ran one tile too many for sub-tile 0, which is why s = -2e29 still differed at rows 32+.
2. Block-wide bound without the clamp (the refuter's probe). Rejected by the experiment above.
3. Different per-tile mask or alpha rule in the extra tile. Rejected: after the bound fix everything matches with the old mask and alpha code unchanged.

Side finding: the original A=1 instance `k_attn_fa2<1,1,true,5,1,true>` also mismatches (seed 3, N = 100, rows 96+, 24576 diffs on c1p1e29 and c2e29, `g25-negctl.md`). The refuter's A=1 control only used seed 1, N = 48, where the clamp is a no-op. Cause is the n - 1 clamp alone: row 96-99 block, original ran tile 8 (lastpos 137), vendor stops at tile 7 (min(111, 99) + 26 = 125).

## Fix (`rewrite/kernels/attn_fa2_c.hip`)

`fa_core` takes the block's last query row (`blast = (tile * NSUB + NSUB) * 16 - 1`, passed by `fa2_body`) and computes
`lastpos = min(blast, n - 1) + base; ntiles = lastpos < -15 ? 0 : (lastpos + ((lastpos >> 31) & 15)) / 16 + 1`. The listing cites are in the comment above that code. Nothing else changed. `attn_fa.hip` still includes the original `attn_fa2.hip` (its call signature is unchanged there).
