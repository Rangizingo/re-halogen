## Caveats

- P8: v10..v13 are never written in the listing, yet the output is deterministic. Measured on the vendor kernel with a one-hot state (state row k0 = 1/16, all else 0, all other inputs 0, 16 runs): A[m][k] = f16(((m + (k & 7)) & 7) / 8), m = lane & 15 (equivalently tid & 7), identical in all four waves, and the second half of k repeats the first. The rewrite uses that pattern (`(lr + (j & 7)) & 7) * 0.125`). It was measured through the oi (q) chain; the w chain is covered by the state output matching on all specs. Sum check: o = 56/256 = 0.21875 with B = 1 (8 k-steps x 2 x 3.5). This is read from hardware, not from the listing; the cvt_f32_ubyte0 / and 7 sequence at p8 lines 92-146 is the visible part of its generation (inferred).
- P5: the A table is read from LDS that this kernel never writes. The vendor result equals the rewrite with A = 0 (MATCH 30 of 30 rows); the negative control with the real k*e table MISMATCHes. So LDS read as zero in every run here. LDS is not zeroed by hardware in general, so this is empirical on the shared GPU (Hermes also runs there), not guaranteed. If a later run shows P5 mismatches, suspect stale LDS first.

## Edge constants
