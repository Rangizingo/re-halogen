## Findings that mattered

- lq6k: weight = bf16_rne((d*scale) * (q-32)), d f16, scale int8 (fma_mix with -0 addend, exact). Group = 16 elements per lane, 210-byte blocks.
- Wave work split: group range [w*ceil(G/W), min(G, ...)), lane stride R; row = blockIdx*(256/(R*W)) + tid/(R*W); token m at x + m*K, y + m*N.
- lq6w weights are planar (ql plane, qh plane, f16 scale/bias plane per 64 elements, row stride (3K/4 + K/16 + 15) & ~15); value = bf16_rne(fma(q, scale, bias)), q unsigned 6-bit (no -32).
- grp: member select by start-block thresholds; W_eff = (N > 8) ? W : 8 (v_cmp VOP3 words that the old listing shows as `.long`); epilogue modes 0 bf16, 1 silu(scale*x) bf16, 2 sigmoid bf16, 3 2*sigmoid(scale*x) f32, 4 sigmoid f32, 5 bf16 split store into y1/y2 per 256 rows, mode > 5 no store. LqGrp layout: member stride 0x48 (w@0, y1@8, y2@0x10, rows@0x30, scale@0x38, mode@0x3c, start@0x40), count@0x120.
- A first grp run showed MISMATCH for M >= 5: my LDS index used a fixed stride of 8 per row (overflowed `part`); fixed to rib*W_eff+wave. Also mode 5 on a small member races in the vendor itself (token stride N/2 overlaps), so mode 5 is only specced on member 0 with rows a multiple of 512 (set C).
