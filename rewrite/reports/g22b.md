## k_dv_quant (NF4 quantizer, listing 8421-13776)

Prologue and addressing are as k_dv_quant8 (tid 64-bit, nb = (A+bias)>>5, r/b by 64-bit divide, rows `src[r]*A + 32*b`). Kernarg: x@0, dst@8, src@16, n@24, q@32, soff@40 (long), A@48.
- absmax: `v_max3_f32` chain over |x| starting `max3(|x0|, 0, |x1|)` (`:8667-8726`).
- 16 NF4 levels are bf16-exact immediates stored to the thread's LDS slice (`:8712-8716`; values in the .hip: -1, -0.6953125, -0.5234375, -0.39453125, -0.283203125, -0.1845703125, -0.0908203125, 0, 0.0795898, 0.1611328, 0.2480469, 0.3388672, 0.4414063, 0.5625, 0.7226563, 1). The f32 table at rodata 0x46b30 (analysis/closure/dv-quant-r4.md) is the host copy used by the consumer; the kernel uses these rounded values.
- 8 candidates `i = 0..7`: `f = fma(float(i), -0.05f, 1.0f)` (`s_fmaak_f32`, s9 = 0xbd4ccccd set at `:8616`), `sc = f * absmax` (`:8743-8744`), skipped when `!(2^-25 < sc)` (`:8747`), `h = f16(sc)`, `d = float(h)`, `t_k = x_k / d` (IEEE division), index = count of 15 strict midpoints `m < t` (midpoint literals in the .hip, ascending), `e_k = fma(-lut[idx], d, x_k)`; error `err = e1*e1`, then `fma(e0,e0,err)`, then `fma(e_k,e_k,err)` k = 2..31 (`:8984` and the dual-fmac chain). Selection: `err < best` strict, best starts +inf, best scale starts as f16 0 (`:10971-10973`, `:8707`, `:8711`).
- Output: scale f16 at `q + soff + dst[r]*(2*nb) + 2*b` (`:13748`); if `!(0 < float(bh))` (`v_cmp_nlt_f16`, `:10989`) all 16 code bytes are 0x77 (`v_mov_b16 v0.h, 0x77`, `:10996`, `:11000`; nibble 7 = 0.0); else byte j = idx(x[2j]) | idx(x[2j+1]) << 4, to `q + dst[r]*(A/2) + 16*b + 64 + j` (`:10997`, `:11334` ... `:13747`).
- Matched first try on all five specs, so nibble order (even element in the low nibble) is settled; `dvq_pack` swaps it and mismatches.

## k_i4r_rows_gl<R>, gl_o<R>, gl_g<R,G>

All three families launch two independent jobs; blocks `< nGemv` (last int kernarg: 160 for gl/gl_o, 176 for gl_g) run P2, the rest P1.

- I4rSd (88 B by value) layout, read from the P1 scalar loads (`:1870949`, `:1870954`, `:1870957`, `:1870958`): +0 HT tile base, +8 su (f16), +16 sv (f16), +24 gate array (bf16 rows of K), +32 up array (bf16, may be null), +40 out (bf16), +48 Pf (f32 split-K partials), +56 u32 tickets, +64 nrows, +68 ld (Pf row stride in floats and out row stride in elements), +72 K, +76 chunk (128-blocks per split), +80 nsplit, +84 unused. The same struct and "dense path" appear in the g14 BLOCKED items (`HtSd`); gl is a readable instance of it.
- P1 (dense HT, `:1870954-1872258` for gl<1>): see the header comment of `gl_p1`. Template argument R is the number of token rows (loop bound `R*nb`, GEMV accumulators and epilogue per row); the activation row r sits at LDS `r*5120 B + block*256 B`, i.e. the GEMV reads row 1 at a fixed +5120 B (checked on gl<2>, `:1875202`), so for R = 2 the prelude addresses `row*5120` (`v_mul_lo_u32 0x1400`, `:1874778` in gl<2>, `:1871074` in gl<1>). Weights: 4-bit HT tiles, tile = 128 B, 128-row tile blocks, decode exactly as g14's ht_dec (hash 0x83dcd12d, byte sum, `fma_f16(S, 0x1eee, 0xc931)`). Tile of column tile ct, row tile i: `wht + ((rt*(K/16) + sp*chunk*8 + ct)*8 + i)*128`. Warp w owns column tiles `[w*nb, (w+1)*nb)` of the split. Partials: `part[w][row][16 i + r] = acc + acc(lane^16)`; block total = `0 + P0 + ... + P7`; nsplit >= 2 stores `pf[(sp*R+row)*ld + rt*128 + t]`, ticket per row tile, the last arrival re-sums splits ascending from 0 (including its own, from memory) and resets the ticket. Epilogue (warp `row` < nrows): 128-point WHT (in-lane over i bits 0,1,2 then xor 1,2,4,8), `* 0x3db504f3`, `* sv` (f16), bf16 RNE, `out[row*ld + rt*128 + 16 i + r]`.
- P2 for gl/gl_o (`:1872260-1874646`): routed-expert gate/up GEMV (K = 2560, 1280 rows per expert, 20 blocks per slot, x row = slot/10) writing y f32, ticket `slot*5 + (blk%10)/2` with four arrivals (two gate blocks, two up blocks), the fourth runs the k_i4r_gu_epi item (a@40, bq@48, out@56 f16 `[slot][640]`) with its first 32 threads and resets the ticket. g22's i4r_gu.hip pipeline is reused unchanged.
- gl_o: `slot = sel[blockIdx/20]` replaces the slot for x row, rowmap, y row, ticket and out row; blk stays `blockIdx - 20*(blockIdx/20)`. The P1 half is byte-identical to gl (instruction diff of the two listings differs only in the P2 prologue and register names). Spec uses `sel = 0,2,4,...` with half the launch (a reversed permutation is invisible because each slot is still computed exactly once).
- gl_g<R,G>: P1 as gl<R> (sd at kernarg 88); P2 is the HtItem-grouped form of the gate/up job (`:1865527-1868798` for <1,2>): item = blockIdx/20, expert/begin/end from `items[item*5]`, up to G slots share the weight loads, per-slot y rows `sid*1280`, tickets per slot by `tid < ns`, epi by warp `w < ns`. First template argument is R, second is G.

## Negative controls (`rewrite/tables/g22b-negctl.md`)

MISMATCH (all of seeds 1,2,3 unless noted): dv_quant 0x77 -> 0x76 on `g22b_dv_quant_edge` (zero-scale path), nibble order swap, candidate step -0.05 -> -0.06; fl_g bias `n-8` -> `n-7`, fold constant 0x3db504f3 -> 0x3db50400 (`g22b_fl_g4_t3`, 28-37 diffs); gl silu exp scale -1.4427 -> -1.44 on `g22b_gl1_p1_edge` (P1) and on `g22b_gl1_p2_small` (P2: gate values must be O(1), the `_edge` spec saturates silu and does not see it), HT hash 0x83dcd12d -> ...2c, 0xc931 -> 0xc930, gl_p2 ticket threshold 3 -> 2, split-K re-sum dropping the last split on `g22b_gl1_p1_s3`, gl_o `sel` ignored on `g22b_glo1_p2`, gl_g expert `^ 1`, gl_g guard `item >= cnt` -> `item > cnt` on `g22b_glg14_t3_p2_short`; gl C constant 0x3db504f3 -> 0x3db50400 on `g22b_gl1_p1_small`: 2 of 3 seeds mismatch (1 to 3 of 576 outputs; seed 2 matches), a weak control.

Controls that still MATCH, kept in the table as evidence and explained:
- `dvq_thr` (2^-25 -> 2^-28 candidate guard): unobservable. Below 2^-25 the f16 rounding gives `h = 0`, a zero scale takes the 0x77 path, and the evaluated error cannot beat a valid candidate. The guard only skips work.
- `dvq_ord` (error accumulation order e1, e0 vs e0, e1): differs only in the last bit of `err`, which never changed a selection in 92k bytes x 3 seeds. The order is read from `:8984` and kept.
- `flg_thr` (`old == 19` -> `18`): the race window is narrow, as in g22.
- `gl2_row` (drop the `min(row, nrows-1)` clamp): unobservable, since rows >= nrows never reach the output; the clamp is memory safety.

## Qualifications and untested

- Tickets use `__threadfence` + atomics like g22's fl; correctness of a race is shown by identical results, not proof (threshold mutants fail where they change the result).
- gl<2> reads the second x row at a fixed +5120 B; specs use K = 2560 for R = 2 (K = 640 only for R = 1, `g22b_gl1_p1_k640`). A launch with R = 2 and K != 2560 would read stale LDS in the vendor.
- Not tested: nrows > R, nsplit giving empty splits (nb <= 0), K not a multiple of 128, tile counts that make `cpw*8 > nct`, HtItem `tile` values other than 0..4 (unused), experts beyond 0 and 1, NaN/Inf in the gate arrays of P1.
- Weights are random bytes (HT tiles) or random f16 blobs (i4r rows and scales), not real checkpoints.
- The `y` scratch of P2 is compared (`-99` marks untouched rows); Pf and tickets are not compared except through outputs.
