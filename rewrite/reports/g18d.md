# g18d report (attn_qs<2,0> and attn_qs<3,0>, codeobj_1513000, primed rows)

All MATCH rows here are CONDITIONAL ON PRIMING. The vendor kernels read 48 KiB of LDS they never write (g18c.md, "qs<2,0> and qs<3,0>": V is two `ds_load_b128` per lane at `w*0x3000 + 0x800 + 48*col + 768*c + {0,16}`, no `ds_store` reaches that range, no global V load). Their output is undefined unless something else filled that LDS. The rows below say: with a priming kernel that fills LDS with a known pattern, the vendor kernel is deterministic and the rewrite (`rewrite/kernels/attn_qs_c.hip`, which models that pattern in `qs_full`) is bitwise equal to it. They say nothing about the vendor kernel on arbitrary LDS contents. Every such row carries `primed` in its result text.

## Harness feature

Spec field `prime` (optional): `{"src": "<.hip path relative to the spec>", "kernel": "<extern C name>", "grid": [x,y,z], "block": [x,y,z], "lds_bytes": N, "args": [...], "kernarg_size": K}`.
- `rewrite/harness/run_kernel.cpp`: after the pre-launch buffer copies and before the measured launch, compiles `src` (if `.hip`) into `DIR/prime.co`, launches it on the same device and stream, then `hipDeviceSynchronize()`, then launches the measured kernel. `args` use the same forms as the main `args` (buffer / value / hex); with no `args` and no `kernarg_size` the prime is launched without a kernarg block (what g18c's scratch driver did). The arg-building loop became a lambda shared by both launches; the main path is otherwise unchanged.
- `rewrite/harness/compare.py`: `prime_src_path` resolves `src` against the spec's directory; `build_run_spec` puts the absolute path into the run spec; the same prime runs before BOTH the vendor and the rewrite run; `result_text` appends `primed`, so the console line and the table row both show it. `--prime-src PATH` overrides the source (negative controls; relative to cwd).
- Tests: `tests/test_compare.py`, 3 new (path resolution and override, prime kept with absolute src and error when missing, `primed` in result text and table row). `python3 -m pytest -q tests/test_compare.py`: 39 passed. run_kernel's side is proven by the Ai-core runs below.
- Priming kernel: `rewrite/kernels/attn_qs_prime.hip` (halfword i of LDS := 0x3f80 + 8*(i & 15), 1000 blocks x 256 threads, 64340 bytes dynamic LDS; same as g18c's scratch `~/g18c/prime.hip`).
- Specs: `rewrite/specs/attn_qs_d_2_0.json` and `attn_qs_d_3_0.json` (copies of `attn_qs_c_2_0.json` / `attn_qs_c_3_0.json` plus the `prime` block; same rewrite file). `attn_qs_d_2_0_noprime.json` and `attn_qs_d_3_0_noprime.json` are the same without `prime`, kept for the variance proof.

## Proof 1: unprimed vendor output is undefined

Spec `attn_qs_d_<p>_0_noprime.json`, seed 1, N=203, vendor kernel, 5 runs (5 separate compare.py processes, each its own run_kernel process), output buffer `o` (37,120 bytes, 18,560 bf16):

| kernel | output bytes differing from run 1 (runs 2,3,4,5) | bf16 outputs identical across all 5 runs |
| --- | --- | --- |
| qs<2,0> | 25,831 / 26,174 / 26,039 / 25,891 | 2,567 of 18,560 |
| qs<3,0> | 26,331 / 19,246 / 26,018 / 25,898 | 2,387 of 18,560 |

Rewrite vs vendor without priming: MISMATCH (18,432 of 18,560 elements differ, max_ulp 65536, first_diff=0), every run.

## Proof 2: primed vendor output is deterministic and matches

Same procedure with `attn_qs_d_<p>_0.json` (with `prime`): 5 vendor runs, 0 differing bytes between runs for both kernels, 18,560 of 18,560 bf16 identical; each of those compare runs printed MATCH ... primed.

Table `rewrite/tables/g18d.md` (written by compare.py on Ai-core): qs<2,0> and qs<3,0>, seeds 1,2,3 x N = 40, 203, 411 = 18 rows, 18 MATCH bitwise, 0 MISMATCH, all `primed`. N=411 and N=40 are in addition to the required two sizes (40 and 411 span below and above the table length; 203 is ragged). Fills are g18c's (q,k in [-2,2], v in [-1,1], gate in [-4,4]); `attn_qs_d_3_0.json` keeps g18c's N+700 row buffers because probe 1 masks the K row index with 0x1ff (g18c.md, last paragraph of that section). `exclude` is not used (no `excluded=` in the table).

## Negative control: shifted priming pattern

compare.py with `--prime-src`, so vendor and rewrite are both primed with the changed pattern; the rewrite ignores LDS (models the original pattern), the vendor reads the changed LDS. Copies of the priming kernel in `~/g18d/negctl/` on Ai-core, made with sed from `attn_qs_prime.hip` (cmp checks that each differs from the original):
- `prime_base`: base 0x3f80 to 0x3f81.
- `prime_shift`: index `(i & 15)` to `((i + 1) & 15)`.

Table `rewrite/tables/g18d-negctl.md`: seeds 1,2,3 x N = 40, 203, both kernels, both controls = 24 rows, 24 MISMATCH, 0 MATCH, all `primed`. prime_base: 16,640 to 16,759 of 18,560 elements differ (max_ulp 2). prime_shift: 16,327 to 17,811 differ (max_ulp up to 60).
