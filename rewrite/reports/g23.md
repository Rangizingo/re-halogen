## Spec design

- SampleRow inputs are binary files `g23_data/rows_{a,b,c,edge,z}.bin` (32 B rows: temp, top_k, top_p, min_p, seed, pos, tag). rows_a: top_k 20 + top_p 0.95, top_p only, top_k only, no filter. rows_b: loose filters. rows_c: row 0 has no filter. rows_edge: top_k 1, top_k >= n (inactive), top_p 1e-6, top_k 3 + min_p 1.0 + T 0.05. rows_z: T 1e-30, T 0, T 1e30, top_k 4095.
- The multi-block chain (max, level0..3, mass, rmass) keeps its state in the scratch buffer. Single-kernel specs for level1..3, mass, pick, accept, qwrite, rmass, rpick take the scratch (and the mass/rmass scan and partial arrays) from `g23_data/scr_after_*.bin`, `out_scan_after_*.bin`, `out_part_after_*.bin`. Those files were produced by running the VENDOR kernels in sequence on Ai-core (x = rand f32 in [-5,5], seed 1, N = 100003 or 4099, `_c100003` / `_c4099` specs fix N and seed to match), so the stored state is consistent with x and the selection logic runs on real data. Suffixes: none = rows_a, `_edge`, `_rb` = rows_b, `_rc` = rows_c, `_tie` = x with ties, `_n4099` = N 4099, `rmassbig` = rmass run with q = 1.0 (no positive residual, rpick/resid fall back). The non-`_c` specs of the same kernel use the same state with different x data (inconsistent state, still deterministic) to hit the end-of-list and no-result paths.
- Ties: x filled as u16 pairs so f32 bits are h<<16|h with h in [0x3e80,0x4100): 640 distinct values, many exact ties, including at the Tkey cutoff.
- x has 256 bytes of front padding and the kernel gets `byte_offset 256`, because pick/rpick/sample/resid read x[row*n - 1] when no element is selected.
- Compare rule: the harness marks a spec failed when an output buffer is untouched. smpg_rmass_edge drops the scratch buffer from its outputs for that reason (kept mass is zero there, so the block totals written are 0 = the input). With temperature 0 in row 0 of resid, both vendor and rewrite write nothing (no thread qualifies); that case is only recorded here, rows_z puts T 1e-30 in row 0 and T 0 in row 1 (a multi-row kernel).

## Non-obvious findings

- Scratch layout (0x4048 bytes per row): +0x0000 f32 block max, +0x0400 f32 block sum of w, +0x0800 f32 kept mass per block (mass), +0x0C00 f32 residual block totals (rmass), +0x1000 u32[4][256] digit counts, +0x2000 u64[4][256] digit masses (45-bit fixed point), +0x4000/+0x4010/+0x4020 prefix, count, mass after level 1 (+4, +8 for levels 2, 3), +0x4040 Tkey. Block 0 of smpg_max zeroes both histograms.
- Draw: u = float(u24) * 2^-24 with u24 = top 24 bits of a splitmix64 style mix of seed ^ (pos * 0xd1b54a32d192ed03) ^ (tag * 0x9e3779b97f4a7c15), then the usual two multiplies; only the high 32 bits of the last product are computed (pick:6248-6283). Same code in rpick, sample, resid.
- Result rule of pick, rpick, sample, resid: the walk returns the index of the LAST kept element it visited. It stops at the first kept element where the running sum exceeds the target, but when the sum never exceeds it (float rounding, inconsistent state) the final kept element is returned, not -1. All branches land on the same `v_mov_b32 v0, v2` block (pick:0x2196F0, 0x219708, 0x219710). My first version returned -1 there; the inconsistent-state specs caught it.
- When no thread or block qualifies the kernels write nothing (ids stay as they were). pick/sample/resid also read x[row*n + result] with result = -1.
- smpg_qwrite, smpg_rmass, smpg_rpick and k_resid_sample_f32 are single-row: they read rows[0] and scratch row 0 and never use blockIdx.y.
- rpick/resid fallback: residual path when 0 < R (sum of residual block totals), else (R <= 0 or NaN) they pick from the kept distribution; resid sums fma(invZk, w, acc) in the fallback and rpick adds `cnt[0] += 1` there when cnt is non-null.
- k_accept_prob_f32 tail is the same arithmetic as k_smpg_accept_final (accept = w/Zk or 0, lp = fma(invT, x-mx, -ln Z), mode 3 returns 1.0).
- Tkey selection: Z-based histogram select takes the highest digit that satisfies (top_k active and top_k <= count) or (top_p active and mass >= target); the monolithic kernels scan 255 down to 0 with early stop, the multi-block level kernels take the max qualifying digit (same result because the condition is monotone on real data).
- Fixed point mass: m = trunc(fma(2^45, w, 0.5f)), hi = floor(m*2^-32), lo = fma(-2^32, hi, m), both through v_cvt_u32 (saturating, NaN -> 0). The ln(sum) helper (nll_final, pick, accept, rpick, sample, resid) is v_log_f32 with a two-term correction and a 2^32 rescale below 2^-126.
- `#pragma clang fp contract(off)` is in nll.hip, pen_rep.hip and smpg_common.h. In nll_final the compiler fused `hi + lo` into an fma (seen in the disassembly of my first build, together with a mistyped ln2 constant); after both fixes the wide-range spec and the 1e6 point sweep MATCH.
- pick's rank filter (key >= Tkey) only changes the result in the end-of-list case, so it is not reachable from a pass/fail spec on these data (negative control below stays MATCH).
