## LqGrp branch of k_hc8_fused and k_hc8_fused3 (rewritten, MATCH)

Each hc8 kernel is several kernels in one grid. `k_hc8_fused<N>`: blocks `0 .. nblk-1` (int kernarg 0x138, `codeobj_53000.s:167335,167340-167341`) run an "lq8" grouped matvec over the LqGrp members, blocks `>= nblk` run the hc8 path. `k_hc8_fused3<N>`: blocks `< rows` (kernarg 0x20) run `k_hc_scatter_norm<false>`, blocks `rows .. rows+nblk-1` run the lq8 matvec (block index relative to `rows`), the rest run the hc8 path (`:182601-182614`).

The first round of specs used `nblk = 0`, which never reaches the LqGrp code. The coordinator asked for specs that drive it, so the lq8 branch is now rewritten (`lq8_role<N>` in `hc8.hip`, cites in the comment, `f1 :168433-169043`, `f3_1 :183706-184032`) and compared by `hc8_lq_N.json` (fused) and `hc8_f3lq_N.json` (fused3), N = 1..8, 96 MATCH rows in `tables/g11-lq.md`. The specs use 4 LqGrp members (count 4) and nblk = 24:

| member | R | rows per block | E (epilogue) | out |
| --- | --- | --- | --- | --- |
| 0 | 12 | 4 (R > 8) | 0 (bf16 store) | bf16 |
| 1 | 5 | 1 (R <= 8) | 2 (sigmoid, bf16) | bf16 |
| 2 | 3 | 1 | 1 (silu with f = 0.75) | bf16 |
| 3 | 9 | 4 | 3 (2 * sigmoid with f = 1.25, f32) | f32 |

The lq8 matvec: row layout = hc8 row layout (K code bytes, then K/16 bytes of (scale, bias) f16 pairs, one per 4 chunks; stride 17K/16; K = kernarg 0x130 / 0x158, activations = kernarg 0x128 / 0x150, N columns at `xa + j*K`). Weights `bf16_rne(fma(byte, scale, bias))`, 8 `v_dot2_f32_bf16` per 16-weight chunk, lane partials added in order, 32-lane xor butterfly, then a per-row sum of the wave partials in order from 0. R <= 8: 1 row per block over 8 waves; R > 8: 4 rows per block, 2 waves per row (my first guess had these swapped; the harness showed the vendor leaving rows 2..4 of member 1 unwritten, which fixed it). E epilogue is the same as in g08's k_dn_conv_ab_rows.

Not covered by specs: E = 4 and E = 5 (E = 5 needs R > 256), R above 9 rows with more than 3 blocks per member, `count` < 4 (the member pick code is the same loop as g08's). `woff/soff/sstride` of the LqGrp members are not read by this branch (checked in the listing), the specs leave them 0.

The earlier hc8 rows in `tables/g11.md` (hc8 path and scatter role, `nblk = 0`) were produced by the build of `hc8.hip` before the lq8 branch was added; the new `hc8_lq_N` / `hc8_f3lq_N` specs run the same hc8 and scatter code through the final build, with 96 further MATCH rows.

Other harness-visible facts for the hc8 kernels:
- hc8 blocks wait on a u64 counter (`global_load_b64 glc` spin, `s_sleep 1`) until it is `>= target` (`:167423-167439`). `k_hc8_fused`: ctr/target at kernarg 0x160/0x168; the spec sets ctr = 5 and target = 5 so the wait passes.
- The counter increment (`global_atomic_add_u64`, `:169061`) belongs to the LqGrp path; the hc8 path skips it (`s_cbranch_vccz 843` at `:168432` lands on `s_nop` at 0x2ff718, after the atomic). So ctr is not an output of `k_hc8_fused` specs.
- `k_hc8_fused3`: the hc8 path waits on ctr2 (kernarg 0x198, target2 0x1a0), which the LqGrp role bumps. With no LqGrp blocks the spec aliases ctr2 to the scatter counter ctr (kernarg 0x188, bumped once per scatter block, `:184331`) and sets target2 = rows, so the hc8 blocks start only after every scatter block finished. ctr is a compared output there (final value = rows).
- In `k_hc8_fused3` the scatter output `out` (kernarg 0x150) is also the hc8 `wm` (mixing weights `[set][plane][2560]`): the epilogue loads it with `s20:21` (`:183552`). Rows = 4 * N.

## Kernel notes (non-obvious decoded facts)

- hcup4<A,B>: B=2 hashes 16 code bytes per lane (xor of four dwords, `v_cvt_f32_u32`), times an f16 scale; B=0/1 decode via a 256-entry LDS table (low half = bf16(cb[v & 15]), high half = bf16(cb[v >> 4]), cb = 16 f32 at W) and `v_dot2_f32_bf16`; B=1 shares one code row for all planes and sets. Sets j>=1: B=0/1 dot x set j (x + 640*j bytes) and run the same sigmoid chain; B=2 uses constant 0.5 weights.
- hc8: u8 codes, row = 20 chunks of 16 bytes + 5 group dwords (f16 scale low, f16 bias high) at +320; weight = bf16_rne(fma(float(byte), scale, bias)); plane stride 870400 bytes (2560 rows * 340). N<=4: 16 rows per block, planes in-lane. N>=5: 4 rows per block, plane = (tid>>4)&3, N dot results rounded to bf16 into LDS, then a combine step with threads `tid < 4N`.
- hcup4w: A = X (tokens, global), B = W (global; the vendor stages it through LDS), D per tile; epilogue is the hcup4 set-0 chain with per-token wm.
- Rounding everywhere: bf16 RNE without NaN special case (`v_bfe_u32 16,1` + `v_add3_u32 0x7fff`); sigmoid = `1 / (1 + exp2(x * -1.442695))` with `v_exp_f32` and IEEE division; `fma(.., 0)` first terms and `0 + x` first adds are kept (they matter only for -0).

## Test data notes

- hcup4/hc8 weights come from one `rand f16` buffer per spec (codes = arbitrary bytes). Ranges are chosen so the sigmoid inputs are O(1): hcup4 B=0/1 f16 in [1.25, 1.5] (codebook f32 = pair of f16 halves, about 0.03 to 0.12), hcup4 B=2 f16 in +-2e-7 (denormals, hash about 1e5), hc8 f16 in +-0.01. Checked on the vendor output that y/f are not saturated (hundreds of distinct values per set).
- Sizes are block counts (grid x) for hcup4/hc8 (37 and 160; hc8 N>=5: 53 and 640, 4 rows per block), token counts for hcup4w (40, 133).
- Unexercised rewrite branches: none other than the LqGrp gap. Null-pointer branches of f/lo are covered by the `_nof`/`_nolo`/`_nofnolo` specs.

## Edge and small-magnitude specs (BRIEF addendum)

Constants in my rewrites that only matter at small or edge magnitudes:
- The RMS epsilon `0x358637bd` (about 1e-6) in `k_hc_scatter_norm<false/true>` and the scatter role of `k_hc8_fused3`. With the wide specs (inputs +-4) the sum of squares is about 2560 * 5, so a different epsilon would not show. Edge specs `hc_scatter_norm_f_small`, `hc_scatter_norm_t_small`, `hc8_f3_1_small` use y0, p, w in [-0.001, 0.001] (variance about 1e-6, same size as the epsilon): 18 MATCH rows in `tables/g11-edge.md`. Negative control: epsilon changed to `0x3727c5ac` (1e-5) gives MISMATCH on all three small specs (`tables/g11-edge-negctl.md`, 3 rows, e.g. 20448 of 41088 elements differ).
- The denormal rescue (`var < 2^-126`, scale 2^24, then 2^12) cannot be reached: `var >= 1e-6`. Not testable, copied as in the listing.
- Sigmoid saturation and exp overflow/underflow (`v_exp_f32` on large inputs, NaN/inf patterns): covered by `inject_gate_exh` and `hc_di_epi_exh` (all u16 patterns) and by the unscaled wide hcup4/hc8 data where sigmoid inputs reach about +-10.
- Clamps and guards: `min(ntok - 1, row)` in k_hcup4w (ntok 40 and 133, both ragged); `row < R` and `tid < 4N` guards in hc8 (ragged block counts); the `lane < 4` second chunk of hc8; the `f`/`lo` null checks (the `_nof`/`_nolo` specs). The `+ 0.0f` first terms only matter for -0 and are kept.
